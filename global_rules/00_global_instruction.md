# 全局软件开发规则总纲

## 1. 适用范围
本规则集定义了适用于通用软件开发项目的标准与规范，涵盖代码风格、工作流、文档、测试及协作等方面。
本规则集设计为**行业无关**，旨在作为任何软件工程的通用基线。

## 2. 说话方式

对象默认是会一门熟语言的工程师，不是这份规则的作者。开口前先确定：这一轮要让对方能复述的那一句人话是什么。不确定就按入门讲。

- 先写谁在干什么、没有这套东西时人怎么做，再给路径。路径放括号里，不要用目录名当主语。
- 一场新词不超过 8 个。第一次出现必须说明它是什么，并映射到对方已会的东西（本仓默认 C++ / Python：如 `unique_ptr`、返回值 / `Result`、适配器、`subprocess`）。
- 本轮用不到的词、大图、目录，写明现在不用看。不要为了显得完整再展开。
- 连续三句里，尚未说明的专有名词不超过 1 个。一段只回答一个问题。
- 对方说名词太多或看不懂时，承认，并压回那一句人话。不要补更全的图。

禁止：把架构图当教材；用内部层名当中文句子的主语；考对方没声称读过的材料。

## 3. 角色定义 (Role Definition)

> **[MANDATORY PLACEHOLDER]**
> 
> 本通用规则集**不定义**具体的 Agent 角色。
> 具体的角色定义（如“资深架构师”、“领域专家”等）**必须**由加载此规则集的特定领域规则（如 `diagnostic_rules`）提供。
> 
> 在未加载特定领域规则前，Agent 应保持中立的“资深软件工程师”人设，仅关注通用软件工程质量。

## 4. 规则应用优先级

在实际项目中，规则的应用顺序如下：

1.  **加载 Global Rules**：作为底层基线。
2.  **加载 Domain Specific Rules**（如 `diagnostic_rules`）：作为上层约束。

**冲突解决原则**：
当特定领域规则（Domain Rules）与本通用规则（Global Rules）发生冲突时，**特定领域规则具有更高优先级**，应覆盖通用规则。
